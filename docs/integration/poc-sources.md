## Prepare and verify the samples

Run from the Explorer root with its pinned Node runtime:

```sh
node --experimental-strip-types scripts/prepare-samples.ts
node --experimental-strip-types --test tests/catalog.test.ts
```

Preparation fetches only each active entry’s declared `files` into ignored `public/generated/`: the playable SIDs, prepared reference WAVs, license copies and required SID-Wizard notice copies. Every entry declares exactly one reference source: a hash-verified `files.reference` prepared locally, or a pinned external `referenceUrl` excluded from preparation. The Rambo stereo WAV uses the external form because its 34,108,544 bytes exceed the unchanged 25 MiB per-asset ceiling. Its exact source fingerprint is recorded below; opening the external link does not pass its bytes through the preparer. Optional `stereo` download links and `materials` links remain outside preparation; only separately declared active entries become playable catalog targets. Every download has a 30-second cancellation deadline, a declared byte-length bound and a 25 MiB hard ceiling. It verifies both byte length and SHA-256 before writing a file. Existing files are reused only after the same checks; a mismatch fails and requires explicitly removing or correcting that local file. HTTP errors, redirects, missing bodies, oversized streams and truncated files fail. The module can be imported by tests without starting the CLI.

The 2026-10-18 network smoke on Node 26.10.0 reproduced the public license response with `Content-Encoding: gzip`, wire `Content-Length: 12130` and 35,149 decoded bytes. Node fetch exposes the decoded body while retaining those wire headers. The preparer therefore compares Content-Length only for unencoded responses and always bounds, measures and hashes the decoded stream. A regression retains this distinction; the initial unconditional header comparison rejected valid license bytes.

For explicitly selected local development, exact-byte copying uses the same checks and never updates the source repository:

```sh
node --experimental-strip-types scripts/prepare-samples.ts --source-root /path/to/sid-song-crafter
```

The default command has no sibling path or runtime dependency. The declared sample files are ordinary Git blobs at the pinned revision; their `raw.githubusercontent.com` URLs return the actual bytes. GitHub `blob` pages return HTML and are unsuitable downloads. Future LFS objects need a pinned `media.githubusercontent.com/media/OWNER/REPOSITORY/REVISION/PATH` URL; the preparer accepts that form and still checks the materialized object hash, so an LFS pointer fails verification.

## Annotation and listening limits

The [strict snapshot parser](../../src/catalog.ts) retains schema version 1: `stereo`, `files.notices`, external `referenceUrl`, second-chip target metadata and root `materials` are additive fields. Legacy mono snapshots still parse; absent `materials` normalizes to an empty array without mutating the input. Unknown fields are rejected. The parser checks immutable source/file URLs, safe unique filenames, hashes, bounded byte sizes, PAL MOS6581/MOS8580 targets, matching analysis identity, one-based physical voice numbers and finite in-range annotation spans. A target has one SID at `$D400`, or two with required `secondSidAddress: 54304` (`$D420`); a mono target cannot carry a second address. Exactly one of `files.reference` and `referenceUrl` is required. External reference and optional stereo download URLs must use the same pinned raw/media repository revision; materials URLs must use that revision’s GitHub blob path, with identities unique across active entries and materials. These restrictions describe this bounded consumer rather than the eventual producer schema. Bach, Mozart, instrument mix and both active stereo entries declare empty annotation arrays: mono annotations are not copied to stereo hashes and no interpretation or source-time labels are invented for them.

Only the mono Rambo entry carries the three annotations below. Its times use `seconds-from-init` and are rebased from source call 1586 using the declared rate of 50.12457321485099 calls per second: `(sourceCall - 1586) / callRate`. They are labelled **derived** because they map documented execution into that entry's timeline; they are not live measurements or recovered instrument identities.
