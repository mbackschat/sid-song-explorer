# README screenshot harness

Run `pnpm screenshot:readme` from the repository root after installing the pinned dependencies and Google Chrome (`pnpm exec playwright install chrome`). The command verifies/prepares the public assets, builds the current app, starts its own managed local preview server on port 4174 (separate from ordinary tests on 4173, ignoring `EXPLORER_TEST_URL` and refusing an occupied port), runs the capture scenario in headless Chrome, and copies the image to [the published README screenshot](../../assets/screenshots/rambo-playing.png) only after the entire test, including fixture teardown, passes. It stops on any failed step. No sibling repository, ROMs, image editor, ffmpeg or manual server is required.

[The scenario](../../tests/browser/readme-capture.spec.ts) selects `rambo-loader-main`, verifies PAL/MOS6581 and one mono SID, loads the actual SID and presses Play. It waits for at least twelve seconds of playback and further position advancement, then checks nonzero PCM metering, populated registers/writes and nonempty waveform selections and colored pitch traces above the zero-frequency baseline in all three voice canvases. It captures the 1600 × 1280 viewport while the transport still offers Pause. Readiness uses observed state, never fixed sleeps or an exact displayed second. The screenshot is a real running interface; no DOM labels, playback state or canvas content are fabricated. Timing and live register values naturally vary between captures; this is not a pixel-equality test.

The [shared silent fixture](../../tests/browser/fixtures.ts) mutes the output after the analyser so audio and visualizations still execute without speaker output. The scenario checks the silent sinks before capture, and the fixture checks them again at teardown. Failure traces remain in ignored `test-results/`; successful capture candidates are in ignored `build/screenshots/<browser>/rambo-playing.png`. The canonical publication command selects Chrome. The ordinary browser suite also runs the scenario on macOS WebKit, but neither ordinary tests nor CI overwrite the checked-in image. The existing 45-second per-test deadline, single worker and zero retries apply.

Inspect the candidate visually before committing the PNG and its README placement. Confirm the Rambo title, Live SID/Pause state, voice history and inspector are visible and the crop ends cleanly. A failed scenario must never replace the published screenshot. Negative checks on 2026-10-19 omitted Play (rejected by the Live SID guard), temporarily drew all voice frequencies at zero (rejected with zero colored pitch pixels), and restored the old hosted-URL configuration (rejected by the source-isolation unit guard). The original code was restored after each check. Loading alone, inactive traces and an unrelated hosted build cannot qualify as the published playing capture. The harness verifies representative UI activity, not human listening or musical acceptance.

On 2026-10-19, the complete configured local browser suites passed with tracing enabled and retries disabled: 16 tests each, Chrome in 1.9 minutes and macOS WebKit in 1.7 minutes, within the existing three-minute CI browser budget. The opt-in full-song endurance scenario remains outside the ordinary suite. GitHub-rendered README placement was visually checked at 1200- and 390-pixel browser widths: images sit side by side on desktop and wrap on narrow screens.

This follows the scenario-and-assertions approach of [Williams' capture workflow](https://github.com/mbackschat/williams-sound-explorer/blob/main/docs/implementation/web-capture.md), adapted to Explorer’s existing Playwright runner and silence/synchronization rules. It does not import Williams’ fixed-delay steps, ROM dependencies or GIF pipeline.

The current image deliberately shows **mono** Rambo. [STEREO-1](../PLAN.md#exit-the-poc-and-continue-production-work) includes changing this scenario to the cleared stereo Rambo entry, verifying two SID chips/six active voice lanes, and updating the image and caption when live stereo support passes its own gates. Do not substitute a stereo WAV for live SID execution or label the mono capture stereo.
