# README screenshot harness

Run `pnpm prepare:engine` with Docker and Python 3.12 or newer, then `pnpm screenshot:readme` after installing the pinned dependencies and Google Chrome (`pnpm exec playwright install chrome`). The capture command verifies/prepares the public assets, builds the current app, starts its own managed local preview server on port 4174 (separate from ordinary tests on 4173, ignoring `EXPLORER_TEST_URL` and refusing an occupied port), runs the scenario in headless Chrome, and copies the image to [the README screenshot](../../assets/screenshots/rambo-playing.png) only after the entire test, including fixture teardown, passes. It stops on any failed step. No sibling repository, ROMs, image editor, ffmpeg or manual server is required. [Dual-SID validation](stereo.md) owns the engine/browser adoption evidence; successful capture is not a listening verdict.

[The updated scenario](../../tests/browser/readme-capture.spec.ts) selects `rambo-stereo-main`, verifies PAL/MOS6581 and two SIDs at `$D400`/`$D420`, loads the actual SID and presses Play. It waits for at least twelve seconds of playback and further position advancement, then checks nonzero output metering, populated registers/writes and nonempty waveform selections and colored pitch traces above the zero-frequency baseline on both the past and upcoming halves of all six voice canvases. It captures the 1600 × 1240 viewport while the transport still offers Pause. Readiness uses observed state, never fixed sleeps or an exact displayed second. The screenshot must be a real running interface; no DOM labels, playback state or canvas content may be fabricated. Timing and live register values naturally vary between captures; this is not a pixel-equality test. The stereo scenario passed on 2026-10-20 after the retained-history correction described below.

The [shared silent fixture](../../tests/browser/fixtures.ts) mutes the output after the analyser so audio and visualizations still execute without speaker output. The scenario checks the silent sinks before capture, and the fixture checks them again at teardown. Failure traces remain in ignored `test-results/`; successful capture candidates are in ignored `build/screenshots/<browser>/rambo-playing.png`. The canonical publication command selects Chrome. The ordinary browser suite also runs the scenario on macOS WebKit, but neither ordinary tests nor CI overwrite the checked-in image. The existing 45-second per-test deadline, single worker and zero retries apply.

Show the rendered README candidate to the user and wait for review before committing or pushing the visual change, as required by [the contributor guide](../../CLAUDE.md#commands-and-validation). Confirm the stereo Rambo title, Live SID/Pause state, both chip groups, six voice histories, two filter lanes and inspector are visible and the crop ends cleanly. Preserve left alignment for the image, button and any caption. A failed scenario must never replace the published screenshot. Negative checks on 2026-10-19 omitted Play (rejected by the Live SID guard), temporarily drew all voice frequencies at zero (rejected with zero colored pitch pixels), and restored the old hosted-URL configuration (rejected by the source-isolation unit guard). Those checks concerned the earlier mono scenario; the original code was restored after each. Loading alone, inactive traces and an unrelated hosted build cannot qualify as the playing capture. The harness verifies representative UI activity, not human listening or musical acceptance.

On 2026-10-19, the complete configured local browser suites passed with tracing enabled and retries disabled: 16 tests each, Chrome in 1.9 minutes and macOS WebKit in 1.7 minutes, within the existing three-minute CI browser budget. The opt-in full-song endurance scenario remains outside the ordinary suite. GitHub-rendered README placement was visually checked at 1200- and 390-pixel browser widths: the Run button occupies its own paragraph above the unchanged screenshot, with the button and image sharing the same left edge and no visible caption.

This follows the scenario-and-assertions approach of [Williams' capture workflow](https://github.com/mbackschat/williams-sound-explorer/blob/main/docs/implementation/web-capture.md), adapted to Explorer’s existing Playwright runner and silence/synchronization rules. It does not import Williams’ fixed-delay steps, ROM dependencies or GIF pipeline.

2026-10-20: `pnpm screenshot:readme` passed with live stereo Rambo, six populated histories and both shared-filter lanes, then replaced the PNG and matching stereo alt text together. The final 1600 × 1240 crop includes the entire timeline and inspector without cutting into the next panel. Visual inspection of an earlier candidate found blank past activity despite retained observations; the strengthened guard failed with zero past pitch pixels, and passed after connected scheduled/prepared observation composition was corrected. The user approved the rendered README candidate on 2026-10-20 after previews at 1200- and 390-pixel widths showed left alignment and no horizontal overflow; the visual change may be committed.
