# Dual-SID adoption validation

This record owns `STEREO-1` and `STEREO-2` evidence. [The plan](../PLAN.md#exit-the-poc-and-continue-production-work) owns priorities and [the design](../design/web-player-and-analyser.md#evidence-required-before-adopting-the-stereo-backend) owns the acceptance gate. [Mono Safari acceptance](mono-poc.md#completion-audit) does not certify stereo playback.

## Contract and independent checks

The raw binding exposes one complete mono bus per installed chip from one shared C64 execution. Explorer routes chip 1 left and chip 2 right at unity gain without crossfeed. For local files this is an explicit player setting, not recovered composer intent. Both MOS6581 and MOS8580 are required. The stock mix blends buses; inverting that rounded result is excluded.

[The WASM gate](../../scripts/experiments/stereo/verify.mjs) activates only chip A or chip B and compares every active sample with an independently configured shipped mono renderer. It rejects swapped, crossfed, duplicated and attenuated output. Idle buses use a separately rendered inactive mono oracle: SIDLite retains a DC offset, and zeroing volume can add a digi transient, so literal zero is unsound. Muting all voices is compared with that independent reference without DC subtraction or tolerance. The gate also checks chip-indexed writes/registers, non-block seek continuation, raw mono equality and shipped mono compatibility.

Positions, durations and seeks count PCM frames; only the PCM array is chip-order interleaved. Registers occupy 32 bytes per chip; writes retain chip number and local address. Automatic local opening inherits a concrete model when the other declaration is unknown/any and rejects conflicting concrete models before replacing playback. An intentional reload applies the selected model uniformly. Six controls address three voices per chip, preserving shared filters and ring/sync dependencies. Voice changes still rebuild the prepared mix; [the voice-switch decision](../research/seek-performance.md#final-decision-retain-existing-voice-switching-2026-10-20) owns that retained interruption.

The 32 MiB typed-cache cap is unchanged. Stereo Rambo PCM exceeds it, so consumed history can be evicted while unread audio must remain. [Session/cache guards](../../tests/stereo-engine.test.ts) compare split/cached reads, unaligned seeks and chip-specific observations with continuous rendering under a deliberately small cap. UI coverage describes actual retained data.

[Browser routing guards](../../tests/browser/stereo-output.spec.ts) compare PCM submitted to Web Audio with the independent mono oracle on both sides/models. [Inspection guards](../../tests/browser/stereo-inspection.spec.ts) cover chip ownership, six controls, shared filters, local-file privacy and return to mono. Mute, solo and inspection/transport are independent scenarios; each audition sequence verifies pending disabled controls, all six mask bits and full-mix restoration without combining repeated mix rebuilds into the inspection budget. All browser automation uses the silent fixture; software checks do not establish real Safari sound.

## Executed adoption evidence

On 2026-10-20 the real modified-WASM gate compared 44,394 frames per model/chip case, rejected routing/gain mutations and verified continuation after frame 12,347 for 4,093 frames. Its receipt binds exact provenance and verifier hashes and is required by asset preparation. The source bundle includes standalone rebuild instructions; its verifier passed against the built module, but cannot qualify for adoption without project provenance and shipped-mono comparison. A separate clean-room rebuild of the emitted archive was not run. [The experiment](../../scripts/experiments/stereo/README.md) owns reproduction and the measured native-configuration budget exception.

Integration oracles cover both models, split reads, unaligned seeks, eviction/observation coherence, cap-failure recovery and PSID-v1 classification. Both real stereo arrangements matched continuous rendering after a seek to 11.731234 seconds. The complete mono Rambo plus tail matched shipped PCM/observations. Local Chrome/macOS WebKit checks exercised production and development module-loading paths, channel delivery and six-voice inspection.

Separate uninterrupted macOS WebKit runs on 2026-10-20 reached both stereo endings with zero buffer underruns, zero dropped writes and no saturated Int16-limit samples. Rambo delivered 8,527,125 frames with left/right peaks 0.388031/0.379578; Bach delivered 3,886,221 frames with peaks 0.283691/0.283630. These linear full-scale measurements are at the Web Audio buffer input before the silent sink. They establish continuity and gain/clipping behavior for these renders, not audible reference equivalence.

The real-playback screenshot oracle also checks colored pitch pixels in both past and upcoming halves. This guards against choosing only prepared preview data after the PCM cache evicts already scheduled audio: connected retained scheduled observations must still compose with the preview, preserving boundary states without duplicate writes. Unit guards cover seams, disjoint ranges and independent held copies. The user approved the rendered stereo Rambo README preview on 2026-10-20; [the screenshot record](screenshots.md) owns that visual acceptance, separately from listening.

## Dense timeline observations

`CachedSidSession.observe` must distinguish a packet write limit from unavailable source data. Stereo Bach has 25,049 writes in its first ten seconds; the 20,000-write packet ended at 7.982211678 seconds despite complete cached coverage. The independent 5–16-second window ended its first packet at 12.996825524 seconds. These reproduce the same mechanism without relying on one reported viewport.

Explicit continuation lets the player collect contiguous packets for a fixed target. Per-response limits and the audio-cache cap remain unchanged; preview accumulation is separately bounded at ten packets, 200,000 writes and 1,001 original register frames. Gaps/frontier exhaustion stop collection; obsolete sessions are discarded, and viewport changes stop further pagination while useful overlap may remain. Pathological dense/wide requests can still reach aggregate limits and stay honestly shaded. Dropped-write warnings retain the maximum reported count across overlapping blocks rather than claiming an exact sum.

[Pagination guards](../../tests/observation-window.test.ts) and [the real-Bach oracle](../../tests/stereo-engine.test.ts) compare complete 0–10 and 5–16-second windows with continuous rendering: all writes, sampled registers and subsequent PCM must match without changed cache bytes/frontier. On 2026-10-20 those windows returned 25,049/27,550 writes and 502/552 frames, measuring 16.520/2.430 ms and 2,384,079/2,645,821 JSON bytes. These local query/serialization results exclude worker transport and heap overhead. [Browser coverage](../../tests/browser/timeline-preview.spec.ts) checks the 2.93-second seek at default and wider zooms and samples every animation frame during advancing playback. It ran in silent Chrome/macOS WebKit; no new Safari listening verdict is inferred.

## Channel-aware Audio output

Stereo shows separate L/R peak/RMS values, level bars and 36-pixel waveforms with one shared spectrum. Cyan identifies left and gold right; adjacent channel bars keep equal spectrum levels visible. Intermediate layouts place the spectrum beside channel strips; sidebar/narrow layouts stack them. Mono retains its single-channel view. Audio output sits directly beneath Sound inspector; ordered writes remain an expandable, initially collapsed detail.

[AudioMonitor](../../src/audio-monitor.ts) sends one unity-gain path to the destination and taps it with a channel splitter feeding independent analysers. The analysers have no output connections, as permitted by [Web Audio §1.8](https://www.w3.org/TR/webaudio-1.0/#AnalyserNode), so monitoring adds no audible route or mono downmix. Fresh buffers reset channel measurements on load. [Unit guards](../../tests/audio-monitor.test.ts) check graph topology, gain, ownership, exact amplitude calculations, reset and disposal.

[Browser guards](../../tests/browser/audio-monitor.spec.ts) inject independent FFT-bin sine signals with known amplitudes into scheduled buffers. They compare peak/RMS with mathematical values, verify left/right-only ownership, rendered frequency/color, spectrum bars and meter widths, and poll all rendered bands for settling. Waveform amplitude and frequency must satisfy their bounds in the same sampled frame; bounded polling allows live output to settle but still rejects sustained silence or incorrect signals. This channel-routing oracle does not establish uninterrupted scheduling. Raw-chip guards independently compare real SID samples with mono rendering. Layout guards bound stereo panel growth to 40 pixels over mono, reject overflow and check return to mono. On 2026-10-20 silent Chrome/macOS WebKit coverage included 1440, 1024 and 390 pixels with inspected captures. This is software/rendering evidence; device acceptance is recorded separately below.

## Device acceptance

- Actual desktop Safari: play stereo Rambo (MOS6581) and Bach (MOS8580) through their endings, compare retained reference renders for lead/accompaniment placement and coupled/filter passages, and exercise six-voice audition, seek, loop and inspection.
- Recent iPhone: open local mono/stereo files and confirm playback, basic seek/mute, visible analysis and recovery after interruption. This is [bounded compatibility smoke coverage](../design/web-player-and-analyser.md#safari-and-hosting-requirements), not a broad mobile matrix.

On 2026-10-20 the user confirmed “Safari/iPhone stereo results are fine” in response to these checks, closing the human/device gate. Exact browser, OS and device versions were not supplied; none are inferred. This verdict does not accept later third-party library workflows or unrelated interface changes.
