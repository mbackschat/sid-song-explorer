# Dual-SID adoption validation

This record owns `STEREO-1` evidence. [The plan](../PLAN.md#exit-the-poc-and-continue-production-work) owns completion and [the design](../design/web-player-and-analyser.md#evidence-required-before-adopting-the-stereo-backend) owns the acceptance gate. Mono Safari acceptance remains in [the mono record](mono-poc.md); it does not certify stereo playback.

## Contract and independent checks

The raw binding exposes one complete mono bus per installed chip from one shared C64 execution. Explorer routes chip 1 to left and chip 2 to right at unity gain, without crossfeed. This is an explicit player setting for local files, not recovered composer intent. Both MOS6581 and MOS8580 are required. The stock mixer is unsuitable because it blends the buses; inverting that rounded result is excluded.

The [WASM experiment](../../scripts/experiments/stereo/verify.mjs) uses synthetic callable PSIDs with only chip A or chip B active and compares the active output sample-for-sample with an independently configured mono renderer. It rejects swapped, crossfed, duplicated and attenuated output. It also checks chip-indexed traces/registers, an unaligned seek remainder, raw mono equality and compatibility with the published mono WASM. These are software gates, not listening verdicts.

The application contract uses frame counts for position, duration, scheduling and seeking. PCM alone is chip-order interleaved; its scalar length is frames × channels. Registers occupy 32 bytes per chip, and ordered writes retain a chip number plus local register address. Automatic local opening supports uniform chip models, inherits a concrete declaration when the other is unknown/any, and rejects conflicting concrete models before replacing playback. An intentional reload applies the selected model to both chips. Six controls address three voices on each chip; a chip’s shared filter and ring/sync dependencies remain intact. Muting still rebuilds the prepared mix, as recorded by the `VOICE-1` deferral.

The existing 32 MiB typed-cache cap remains unchanged. Stereo Rambo’s PCM alone exceeds that cap; consumed history can be evicted and the UI reports actual retained coverage. Unread audio must never be evicted. [Session/cache guards](../../tests/stereo-engine.test.ts) compare split and cached reads, non-block seeks and chip-specific observations with continuous rendering while enforcing a deliberately small cache cap.

[Browser routing guards](../../tests/browser/stereo-output.spec.ts) compare the samples handed to Web Audio with the independent stock mono oracle on each side for both models. [Inspection guards](../../tests/browser/stereo-inspection.spec.ts) cover chip ownership, six controls, shared filters, local-file privacy and return to mono. Browser tests use the existing silent fixture; neither headless Chrome nor Playwright WebKit establishes real Safari sound.

The common meter, waveform and spectrum analyse `(L + R) / 2` and are labelled as a mono monitor for stereo. This display can cancel opposite-phase signals. It does not alter the output routing: Web Audio specifies that [AnalyserNode passes audio through unchanged while analysing a mono downmix](https://www.w3.org/TR/webaudio-1.0/#AnalyserNode).

Each case compared 44,394 frames with independently rendered shipped mono, rejected crossfed/swapped/duplicated/attenuated mutations, checked chip-indexed writes and retained continuation after frame 12,347 for another 4,093 frames. The generated receipt binds the exact provenance and verifier; production asset preparation accepted it. The source bundle includes standalone rebuild instructions; its standalone verifier entry point also passed against the built module, but that receipt cannot qualify for production adoption without the project provenance and shipped-mono comparison. A separate clean-room rebuild of the emitted archive was not run. Integrated browser evidence follows below; real Safari and iPhone acceptance remain pending.

The [experiment record](../../scripts/experiments/stereo/README.md) owns native build diagnostics, bounded-stage reproduction and the measured configuration-budget exception. The first raw oracle also exposed a false test assumption: SIDLite’s idle bus is a DC offset, not literal zero. The corrected oracle compares every idle sample with a separately rendered stock mono fixture whose voice control is disabled; it does not subtract DC or allow a tolerance. Muting all three voices matches that independent idle reference. Both browser and session guards use the same independent-reference principle.

Focused integration checks passed for both models: split reads, non-block-aligned seeking, cache eviction/observation coherence, cap-failure recovery and PSID-v1 payload classification. Both real stereo arrangements matched continuous rendering after a seek to 11.731234 seconds. The complete regular suite then passed all 40 checks on each browser, with three opt-in full-song checks skipped per browser: Chrome shards took 2.0 and 1.7 minutes; macOS WebKit shards took 2.1 and 1.7 minutes. The separate uninterrupted stereo WebKit checks passed both complete performances in 4.8 minutes, with exact frame totals, zero buffer underruns, zero dropped writes and no saturated Int16-limit samples on either output.

## Dense timeline observations

On 2026-10-20 the user reported a blank upcoming region near 2.93 seconds in stereo Bach. The violated invariant was in `CachedSidSession.observe`: the 20,000-write response cap shortened available coverage even though the cache already held the requested range. Bach has 25,049 writes in its first ten seconds; the first packet ended at 7.982211678 seconds. A second instance, 5–16 seconds, stopped at 12.996825524 seconds. Mono Bach and stereo Rambo did not reach that cap over the same initial span. An initial browser probe was inconclusive because later cache eviction let the remaining suffix fit one packet; it also lacked an audio start required by the silent fixture. The corrected playback/seek guard reproduced a persistent 2.69-second shortfall after one zoom-out, with the failing trace retained locally.

An explicit packet continuation now lets the player collect contiguous observations for a fixed target. The per-response limit and 32 MiB audio cache remain unchanged. Preview accumulation is separately bounded at ten packets, 200,000 writes and 1,001 sampled register frames; it retains exact writes and existing frame baselines rather than inventing intermediate states. Source gaps and frontier exhaustion stop collection, obsolete sessions are discarded, and moving the viewport stops further pages while preserving useful overlap. These aggregate bounds can still limit pathological dense/wide requests; unavailable data remains shaded. Dropped-write counts preserve a warning through the maximum reported count, consistent with the timeline compositor, rather than claiming an exact sum across overlapping source blocks.

The [pagination guards](../../tests/observation-window.test.ts) failed before the helper and passed afterward. The [real-Bach guard](../../tests/stereo-engine.test.ts) failed on the missing continuation, then verified complete 0–10 and 5–16 second windows against independent continuous rendering: all writes, every sampled register state and subsequent PCM match, with unchanged cache bytes and producer frontier. Those windows returned 25,049/27,550 writes and 502/552 frames. Local collection measured 16.520/2.430 ms with JSON-serialized sizes of 2,384,079/2,645,821 bytes; these are object-serialization sizes, not heap measurements, and exclude worker transport. The 57 focused cache/player/pagination checks passed in 19.41 seconds, the real-Bach oracle passed in 1.60 seconds, and the production build passed. [Browser coverage](../../tests/browser/timeline-preview.spec.ts) checks the 2.93-second seek at default density and both wider zoom levels, then samples every animation frame through three seconds of playback at the widest zoom. Existing mono coverage after seeking remains in the same focused run. Both browser checks passed in Chrome (48.5 seconds including teardown) and macOS WebKit (34.9 seconds), with retries disabled and the silent fixture active. The Chrome capture was visually checked: all six lanes extend through the prepared right edge. Timeline/composition and browser-policy guards also passed. No new real-Safari listening verdict is claimed.
